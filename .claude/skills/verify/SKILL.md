# Verify

The single gate for "done" in this repo. Run it after every change to source, config, or dependencies.

## Steps

1. Run the full gate:

   ```bash
   npm run verify
   ```

   This runs, in order and stopping at the first failure:
   `typecheck` (tsc --noEmit) → `lint` (expo lint) → `format:check` (prettier) → `test --ci` (jest).

2. If it fails, fix the root cause, then re-run only the failing step until it passes, then re-run `npm run verify` once at the end:

   | Failing step   | Re-run                  | Usual fix                                                                 |
   | -------------- | ----------------------- | ------------------------------------------------------------------------- |
   | `typecheck`    | `npm run typecheck`     | Fix the type, don't cast it away. `as unknown as` needs a one-line why.   |
   | `lint`         | `npm run lint`          | `npx expo lint --fix` for autofixable rules; fix the rest by hand.        |
   | `format:check` | `npm run format`        | Prettier rewrites files; review the diff.                                 |
   | `test`         | `npx jest path/to/file` | See the `write-tests` skill. Never delete or `.skip` a test to get green. |

3. If you changed dependencies, `app.json`, or `eas.json`, also run:

   ```bash
   npm run doctor
   ```

   and fix anything it reports (usually `npx expo install --fix`).

4. If you changed UI, also see it render: use the `run-app` skill (web preview is the fastest check available on any machine).

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs this same gate on pushes to `master`/`main` and on pull requests, plus a `bundle` job (`npm run check:bundle`: export web with API routes and Android, fail on `LLM_*` names in client bundles). Run `npm run check:bundle` locally after touching Metro config, env handling or anything server-side. The verify job is: `npm ci` → `npm run verify`, plus `npx --yes expo-doctor` in a separate job. A local pass means the CI verify job should pass. The workflow only calls `npm run verify`, so changing the gate means changing that script in `package.json`, not the workflow.

## Reporting

State exactly what ran and what passed. If something could not be checked (e.g. iOS-only code on a Linux machine), say so instead of implying it was verified.

## Notes

- Typed routes (`.expo/types`) are generated by `expo start`. If `tsc` complains about `Href` types after adding a route, start the dev server once (`npx expo start`, then stop it) to regenerate them.
- React Hooks lint rules come from React Compiler (`react-hooks/*`). Treat them as real bugs: the compiler skips components that break the rules.
