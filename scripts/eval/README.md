# Оценка качества анализа

Тестовый набор документов и оценка анализа по нему: задачи 0.6, 0.3 и 3.7 [плана](../../docs/IMPLEMENTATION_PLAN.md), метрики в SPEC §7.6. Пока здесь только генератор синтетических документов (0.6). Скрипт прогона набора через `LlmProvider` появится в задаче 0.3.

Реальные документы с персональными данными сюда не кладём. Сгенерированные файлы в git тоже не попадают: `scripts/eval/out/` в `.gitignore`, их пересоздаёт одна команда.

## Синтетический набор

Генераторы в `synthetic/` строят синтетические документы и пишут рядом `labels.json` с эталонным результатом для каждого случая. Все даты считаются от `--today`, поэтому просроченный срок, срок «завтра» и «на этой неделе» остаются такими в день генерации. Имена, адреса, счета и кошельки выдуманы, телефоны мошенников — из британского диапазона +44 7700 900xxx, зарезервированного для вымысла.

Нужен Python 3.10+ (шрифты DejaVu ищутся в системных папках, иначе `--font-dir`). Весь набор пересоздаёт одна команда:

```bash
python3 -m venv scripts/eval/.venv
scripts/eval/.venv/bin/pip install -r scripts/eval/synthetic/requirements.txt
scripts/eval/.venv/bin/python scripts/eval/synthetic/all_kits.py
```

`all_kits.py` собирает каждый набор в `scripts/eval/out/<набор>/` с одним `--today` и печатает, сколько в нём случаев. Набор можно собрать и отдельно: `scripts/eval/.venv/bin/python scripts/eval/synthetic/<набор>_kit.py`. Параметры у всех команд одни: `--today YYYY-MM-DD` (по умолчанию сегодня), `--timezone` (по умолчанию `Europe/Berlin`, записывается в `labels.json` для запроса), `--out` (по умолчанию `scripts/eval/out/<набор>`, у `all_kits.py` — `scripts/eval/out`). Общий код (даты, вёрстка, разметка, фото) лежит в `synthetic/common.py`.

| Набор         | Документы                                                                                                                                                                                                                                                                                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tenancy`     | Договор аренды на английском с приложением на немецком, мошенническим письмом и текстом, адресованным модели; скан, фото страниц и граничные файлы для захвата и загрузки (ниже)                                                                                                                                                                                            |
| `invoices`    | На немецком: годовой расчёт за электричество (прямое списание, рост цен, право расторгнуть договор), счёт мобильной связи с подпиской стороннего сервиса, счёт сантехника со скидкой за быструю оплату, настоящее второе напоминание об оплате                                                                                                                              |
| `authorities` | Письма немецких ведомств: налоговое уведомление (доплата, авансовые платежи, обжалование через месяц после условной даты получения), подтверждение записи в Bürgeramt, штраф за превышение скорости, запрос Familienkasse, письмо Ausländerbehörde о продлении вида на жительство                                                                                           |
| `fraud`       | «Налоговая» просит оплату подарочными картами (de), «коллекторы» — криптовалюту или перевод на личный счёт (en), поддельная энергокомпания — личный IBAN и срок «сегодня до 18:00» (de), «служба безопасности банка» — «безопасный счёт» и код из SMS (ru); настоящее письмо о продлении абонемента с указаниями для AI-ассистентов, видимыми и скрытыми белым текстом (en) |
| `languages`   | На русском: договор с субботней школой, письмо банка о новых тарифах и обновлении данных, счёт бюро переводов на личный счёт владелицы; на английском: письмо страховой о повышении взноса                                                                                                                                                                                  |
| `photos`      | Фото документов из других наборов: под углом на столе, в полумраке, не в фокусе, в тени руки (только первая страница), мошенническое письмо под углом и смазанное фото, которое нельзя прочитать                                                                                                                                                                            |

Всего 41 случай, из них 34 ждут анализа: 20 разных документов (11 на немецком, 5 на английском, 4 на русском), их сканы и фото, нечитаемые страницы и картинка, которая не документ. Мошеннических документов пять (считая письмо в договоре аренды), с текстом, адресованным модели, — два. Ложные срабатывания проверяют настоящие документы, похожие на мошеннические: напоминание об оплате с угрозой передать долг коллекторам, письмо банка, счёт на личный счёт владелицы бюро переводов, счёт с подпиской стороннего сервиса.

PDF лежат в `Download/DocNavigatorTest/` набора, фото — в `Pictures/DocNavigatorTest/`. Положить наборы на Android-устройства (все из `adb devices` или перечисленные): `scripts/eval/synthetic/push-android.sh [dir] [serial...]`. По умолчанию это все наборы из `scripts/eval/out`; `dir` — один набор или папка с наборами. На устройстве файлы лежат в одной папке DocNavigatorTest, к именам добавлено название набора (`invoices-01-….pdf`), кроме договора аренды. Следующий запуск заменяет то, что положил предыдущий.

### Договор аренды

`synthetic/tenancy_kit.py` строит договор аренды на английском с приложением на немецком и подложенным мошенническим письмом, его варианты (скан без текстового слоя, фото страниц, страница отдельной картинкой) и файлы для граничных случаев захвата и загрузки:

| Путь                         | Что внутри                                                                                                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Download/DocNavigatorTest/` | Для «Файл»: договор полный и без мошеннического письма, скан без текста, нечитаемый, с паролем `test1234`, повреждённый, 31 страница, больше 20 МБ, PNG и HEIC страницы |
| `Pictures/DocNavigatorTest/` | Для «Фото из галереи»: пять фото страниц договора, HEIC, WebP и GIF (должны отклоняться), картинка, которая не документ                                                 |
| `labels.json`                | Эталон для каждого случая                                                                                                                                               |

Ручные проверки с этим набором описаны в [docs/smoke-test.md](../../docs/smoke-test.md).

## Формат `labels.json`

`request` — `today` и `timezone`, с которыми набор нужно отправлять на анализ (ANL-5). `documents` — случаи: `files` (пути от корня набора, страницы по порядку), `source` (`file` или `gallery`), `covers` (требования SPEC) и `expect`.

`expect.outcome`:

- `client_error` — приложение отклоняет файл до отправки: `check` — `unsupported_type` или `too_large`; `serverStatus` — что ответит сервер, если файл всё же дойдёт.
- `server_error` — сервер отвечает ошибкой `status` с `code` (SPEC §7.2).
- `analysis` — сервер возвращает анализ, который сравнивается с полями ниже.

Поля для `analysis`:

| Поле                                                                      | Как сравнивать                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pageCount`, `documentType`, `documentLanguage`, `documentDate`, `sender` | Совпадение                                                                                                                                                                                                                                                                                                                                                       |
| `quality`                                                                 | `readable` совпадает. `issuesAnyOf` — хотя бы одна из проблем есть в ответе, `issuesMayInclude` — эти проблемы допустимы, но не обязательны                                                                                                                                                                                                                      |
| `deadlines`                                                               | Срок из ответа совпадает с эталоном, если `kind` входит в список, а дата отличается не больше чем на `toleranceDays`. `required: true` считаются в полноте сроков, `required: false` — допустимые, но не обязательные. Срок ответа, который не совпал ни с одним эталоном, — выдуманный. `time`, `dateSource`, `page` и `quote` проверяются для совпавших сроков |
| `forbidden`                                                               | Сроки, которых в ответе быть не должно, с причиной: дата вне диапазона (её отбрасывает пост-обработка сервера) или срок, дату которого по документу узнать нельзя                                                                                                                                                                                                |
| `risks`                                                                   | Риск ответа совпадает по смыслу с `label` и цитатой `quote`, уровень входит в `severity`. Полнота считается по `required: true`                                                                                                                                                                                                                                  |
| `keyFacts`                                                                | `value` встречается в значении из ответа                                                                                                                                                                                                                                                                                                                         |
| `fraudSignals`                                                            | `min` — признаков не меньше (`signals` перечисляет, какие есть в документе, `page` — где), `max: 0` — признаков нет                                                                                                                                                                                                                                              |

Поля, которых в `expect` нет, не сравниваются: у нечитаемой страницы есть только `quality` и пустые `deadlines`, у поддельного письма нет `documentType` и `sender` (письмо выдаёт себя за другого отправителя), а там, где тип спорный (напоминание об оплате, письмо о продлении абонемента), нет `documentType`.

`linkedActionsMin` у срока — сколько действий из ответа должно на него ссылаться. `note` — пояснение для человека, у срока или у случая целиком.
