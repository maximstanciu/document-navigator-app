## `Intl` в Hermes

Результаты одинаковые на телефоне и эмуляторе.

| Проверка                           | Результат                                                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `Intl.DateTimeFormat` с `timeZone` | Работает. Europe/Berlin, Asia/Almaty (UTC+5 по правилам 2024 года) и America/New_York посчитаны верно, `formatToParts` есть.   |
| Часовой пояс устройства            | `Intl.DateTimeFormat().resolvedOptions().timeZone` возвращает IANA-имя. Подходит для поля `timezone` в запросе анализа (§7.2). |
| Даты по-русски                     | «31 октября» — родительный падеж правильный.                                                                                   |
| `Intl.NumberFormat`                | `84,20 €` (de-DE), `1 234,50 ₽` (ru-RU). Для тенге в ru-RU выводится код: `1 234,50 KZT`.                                      |
| `Intl.PluralRules`                 | **Нет** (`undefined`).                                                                                                         |
| `Intl.RelativeTimeFormat`          | **Нет**.                                                                                                                       |
| `Intl.ListFormat`, `Intl.Locale`   | Нет.                                                                                                                           |

**Вывод.** Для множественного числа нужен полифил: без `Intl.PluralRules` i18next не выберет правильную форму («1 страница, 2 страницы, 5 страниц»). Кандидат — `@formatjs/intl-pluralrules` с данными для ru, uk, en и de. Если в интерфейсе нужны фразы вида «через 3 дня», ещё `@formatjs/intl-relativetimeformat`; иначе такие фразы собираем из словаря с `PluralRules`. Обе зависимости согласуются в задаче 1.1. Даты, часовые пояса и суммы работают без полифилов.

## «В календарь» на Android

| Шаг                                                         | Результат                                                                                                                                                                                                                                        |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Разрешения в манифесте                                      | После `expo prebuild` в манифесте приложения есть `READ_CALENDAR` и `WRITE_CALENDAR`, хотя мы их не просили (в манифесте самой библиотеки их нет).                                                                                               |
| `getCalendars()` без разрешения                             | Ошибка: `Missing android.permission.READ_CALENDAR permission`.                                                                                                                                                                                   |
| `new ExpoCalendar(id)` без `getCalendars()`                 | Не работает: `Received 1 arguments, but 0 was expected`. Тип в TypeScript конструктор с `id` разрешает, нативный модуль — нет.                                                                                                                   |
| `addEventWithForm()` после разрешения                       | Работает. Внутри это тот же `ACTION_INSERT` с `CALENDAR_ID`. Промис разрешился через 42 мс с `{ action: "done" }`, не дожидаясь пользователя: на Android результат всегда `done`, сохранил ли пользователь событие — неизвестно.                 |
| `ACTION_INSERT` через `expo-intent-launcher` без разрешений | Работает: разрешения отозваны (`status: "denied"`), форма вызывается без ошибок. На этом телефоне два приложения календаря (Google Calendar и Outlook), поэтому сначала открывается системный выбор приложения. После «Назад» — `resultCode: 0`. |

**Вывод.** Через `expo-calendar` на Android форму без `READ_CALENDAR` не открыть: экземпляр календаря получают только через `getCalendars()`. А `READ_CALENDAR` — чувствительное разрешение: системный запрос, объяснение в Data safety, повод для вопросов при ревью в Google Play. Поэтому для Android:

1. «В календарь» — `ACTION_INSERT` с `content://com.android.calendar/events` через `expo-intent-launcher`, без разрешений. Передаём `title`, `beginTime`, `endTime`, `description`.
2. `READ_CALENDAR` и `WRITE_CALENDAR` убираем из манифеста через `android.blockedPermissions` в `app.json`.
3. `expo-calendar` остаётся для iOS: `addEventWithForm()` с доступом только на запись (iOS 17+); iOS 16 — проверить в первой iOS-сборке.
4. Узнать, сохранил ли пользователь событие, нельзя ни одним способом. Интерфейс не пишет «Добавлено», а только открывает календарь.
5. Если календарных приложений несколько и ни одно не выбрано по умолчанию, Android показывает выбор приложения — это нормально.

## Что не проверено

- iOS: `Intl` в Hermes для iOS и «В календарь» на iOS 16 и 17+.
- Android 8 (API 26).
- Устройство без календарного приложения: `startActivityAsync` должен завершиться ошибкой, её нужно обработать понятным текстом.
- Пункт 3 задачи 0.7 (исключение файлов из бэкапа) — только если D-2 = A или C.
